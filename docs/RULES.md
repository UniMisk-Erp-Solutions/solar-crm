## How rules behave

* Rules are **versioned by `effective_from`**; the engine resolves the version in force on the reference date (commissioning date for compliance gates, quote date for pricing, today for SLAs).
* A rule that is **not `verified`, or not active, is advisory only**: it can produce a warning but never blocks a transaction, unless a Compliance Officer explicitly activates it as a hard stop (`enforce_hard_stop`).
* Every gate result stores the `rule_config` ids it used so the decision can be reproduced.
* Every change needs a **source name and source reference** and is audited.
