# Demo scenarios

The demo dataset is **entirely fictional** (names carry "(Demo)", e-mails end in `@demo.futuresolar.local`, mobiles are `+91 90000xxxxx`, GSTINs/PANs are format-valid dummies, no Aadhaar numbers). It is generated by `packages/shared/src/seed` relative to an anchor date, loads automatically in the in-memory demo mode, and is written to the demo block of `supabase/sql/12_seed_reference.sql` by `npm run seed:sql`. Remove it from a real database with `supabase/sql/99_delete_demo_data.sql`.

## 1. Quotations — one per compliance gate, plus two clean quotes

Every gate quote is in status **draft** with compliance status **pending**; the compliance engine evaluates it when it starts. Each quote is built so that it trips exactly the gate it is named for. "Expected" assumes the seeded rule states (verified and active rules can block; unverified, conflicting or inactive rules are advisory and degrade a hard stop to a warning).

## 5. Approvals, clocks and compliance calendar

Commercial lane: approved (W1), rejected by Management (W2 v1), pending at Regional Head (Q-DEMO-P01). Compliance lane: approved (W4 substitution), pending (Q-DEMO-P01). Credit lane: approved, pending and rejected overrides. Running clocks include lead acceptance, follow-up, approval, DISCOM feasibility/commissioning, CFA release, legacy-claim deadline, ALMM exemption, SOP reply/show-cause, grievance, loan ageing, warranty RMA and payment reminders. The compliance calendar and the 26-item verify register are reference data and survive deleting the demo block.
